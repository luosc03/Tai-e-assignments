# A2 常量传播与 Worklist 踩坑记录

本文记录实现 A2 时遇到的 Tai-e IR、常量传播格和 worklist 求解器相关问题。

## 1. 形参不从 CFG entry 的 uses 获取

方法的形参列表来自 `cfg.getIR().getParams()`。`cfg.getEntry()` 是控制流图的入口节点，不代表参数列表；`getUses()` 返回的是某条语句读取的表达式。A2 只分析可保存整数值的变量，因此边界事实中只将 `canHoldInt(param)` 的形参设为 `NAC`。

## 2. CPFact 用缺失映射表示 UNDEF

`CPFact` 是稀疏映射：变量没有映射就代表 `UNDEF`。`CPFact.get(var)` 对缺失变量返回 `Value.getUndef()`，而不是 `null`；调用 `update(var, UNDEF)` 会移除该映射。因此不要用 `get(var) == null` 判断 `UNDEF`。

合并事实时，只遍历输入事实中存在的键即可：目标事实中缺少该键时，读取到的是 `UNDEF`，与输入值合并后得到输入值；目标中有而输入中没有的键与 `UNDEF` 合并，值保持不变。

## 3. DefinitionStmt 不一定有左值

Tai-e 的 `DefinitionStmt` 包含方法调用语句 `Invoke`。例如 `x = foo()` 有左值 `x`，但单独的 `foo()` 没有接收返回值，`getLValue()` 会返回 `null`。所以 `stmt instanceof DefinitionStmt` 并不能保证左值是变量，使用左值前要检查 `instanceof Var`。

对 `x = foo()`，A2 将无法精确求值的右值保守地近似为 `NAC`；无接收变量的调用不定义局部变量，保持输入事实即可。

## 4. 已知除数为 0 时要先于 NAC 判断

A2 规定整数除法和取余的除数为 0 时结果为 `UNDEF`，包括左操作数为 `NAC` 的情况。例如 `a / 0` 中，`a` 若为 `NAC`，仍应得到 `UNDEF`。因此在 `evaluate` 中，若右操作数已确定为常量 0，应先处理 `/` 和 `%`，再执行一般的 `NAC` 传播判断。

同时注意 `/` 使用除法，`%` 使用取余；不要把 `REM` 分支写成 `/`。

## 5. transferNode 的 changed 要比较最终 OUT

`transferNode` 的布尔返回值供 worklist 判断是否需要重处理后继，含义是最终 `OUT` 是否改变。若先把 `IN` 复制到已有 `OUT`，再覆盖赋值目标，中间的更新可能让 `changed` 变成 `true`，即使最终 `OUT` 与旧值相同；循环 CFG 中会造成无谓重复入队，甚至无法收敛。

可靠做法是从 `IN` 构造候选 `newOut`，执行定义语句的更新，再比较 `newOut` 和旧 `OUT`。提交候选结果时也要清空旧映射，因为 `copyFrom` 只复制或更新键，不会删除目标中多余的键。

## 6. Worklist 去重和取出节点

Worklist 需要能避免同一个待处理节点重复排队，同时允许节点出队后因后继变化再次入队。`LinkedHashSet` 可以保留插入顺序并去重；取队首可用 `nodes.iterator().next()`，再调用 `nodes.remove(node)`。

## 7. switch 表达式代码块使用 yield

当 `switch` 作为表达式、某个 `case` 使用 `{ ... }` 代码块时，用 `yield` 返回该分支的值。`return` 会结束整个方法，不是给 `switch` 表达式提供结果。
